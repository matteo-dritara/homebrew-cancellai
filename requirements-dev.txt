# pinned to a tag - `scripts/check_skill_content.py` refuses outright when the installed version is
# not the pinned one, because a scanner that changes what it detects changes the meaning of a
# passing run. It lives here rather than in a separate install step so that one command makes a
# fresh clone able to run every gate.

# repository's test matrix still exercises Python 3.10, where an unconditional requirement makes
# `pip install -r requirements-dev.txt` fail outright. pip skips it below 3.12; the gate then
# refuses on those interpreters and says why. The pre-commit and lint jobs run on 3.14.
